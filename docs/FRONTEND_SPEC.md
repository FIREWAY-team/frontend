## 1. 사용자 정의

### 결정 · **단일 사용자 (상황실 담당자)**

MVP는 **소방본부·소방서 상황실 담당자** 한 유형으로 잡는다. 관리(차량·CCTV 데이터 확인)와 사용(경로 확정)을 같은 계정이 한다.

### 왜 분리하지 않는가

1. **출동대(소방관)는 이 시스템의 "출력" 소비자**다. 경로는 무전·차량 태블릿·프린트로 전달되는 게 현실 — 웹으로 받지 않는다. FE가 별도 모바일 뷰를 만들 근거가 부족.
2. **상황실 담당자가 입력·검토·확정을 다 한다.** 시나리오 선택 → 차량 선택 → 경로 3개 검토 → 확정, 이 흐름의 주체가 한 사람.
3. **관리(차량·데이터)도 실무상 같은 사람이 한다.** 담당자·관리자 계정을 나누면 자기 데스크에서 로그아웃/재로그인이 필요 — 상황실 흐름이 끊긴다.
4. **D-16·FE 1명 · 시연 목적.** 권한 축을 세우면 로그인·세션·라우트 가드·백엔드 계약(role 필드)이 다 늘어난다. 지금 그 자리는 사업 아이디어에 없다.
5. **확장 여지는 컴포넌트 레벨로 남긴다** — v2에서 역할이 늘면 `<CanEdit>` 같은 얇은 가드로 잎사귀만 조건부 렌더링. 라우트를 나누지 않는다.

### 로그인 · 인증

- **시연 계정 1개** (`demo@golmok119` 같은 하드코딩) · httpOnly 쿠키 세션.
- BE와 계약은 `POST /auth/login` · `POST /auth/logout` 두 개만.
- 자동로그인·비밀번호 재설정·회원가입 **전부 안 만든다** — 시연 대상 유일 사용자는 팀이다.

### v2·v3 확장 로드맵 (참고만)

| 시점 | 사용자 확장 |
|---|---|
| v2 (본선) | 관할 소방서 다중 계정. 계정별 `stationId`로 관할 지역 스코프 |
| v3 (실증) | Role: `dispatcher` (담당자) / `admin` (관리자, 차량·CCTV 데이터 수정) 분리 |
| v4 (상용) | 출동대장용 모바일 뷰 · 무전 대체 흐름 |

## 2. 사용자 프로파일 · 사용 맥락

### 상황실 담당자의 일상

- 24시간 교대. 야간 근무 있음 → **다크모드 필수**.
- 대형 모니터(24"+) 위주. 마우스·키보드. **터치·모바일 대응 안 함**.
- 옆에 대형 지도벽·CCTV 모니터 존재. 웹 화면은 **결정 보조 도구** 위치.
- 다른 상황(무전·전화)과 병행 → **한 화면에 필요한 정보를 다 띄운다** (탭 이동 최소화).
- 긴급 상황 시 초 단위 판단. **클릭 3번 안에 경로 확정**이 목표.

### 손·눈·주의력 특성

| 관점 | 설계 시사점 |
|---|---|
| 시선이 지도에 붙어 있음 | 경로 카드·근거 카드는 지도 오른쪽 사이드에, 지도가 가려지지 않게 |
| 색으로 급함을 표현 | **빨강 = 진입 불가/위험 하나만**. 나머지는 명도·아이콘·문구 (z-groupware 규칙 승계) |
| 확정 실수 = 사고 | 확정 버튼은 명시적. 실수 방지용 확인 토스트(2초) → 필요시 취소 |
| 야간 눈부심 | **다크가 기본** · 라이트는 옵션. 순검정 금지(z-groupware 규칙 승계, 최저 `#1A1715`) |

## 5. 화면별 상세

### 5-1. 로그인 (`/login`)

**레이아웃**: 중앙 정렬 카드 (z-groupware `centered` 560px).

**요소**
- 서비스 로고 · 이름 (골목119)
- 이메일 · 비밀번호 필드 (시연 계정 힌트 텍스트 하단에 표기)
- `[로그인]` 버튼
- (없음) 회원가입 · 비밀번호 찾기 · 소셜 로그인

**동작**
- 성공 → `/dispatch`로 이동, 세션 쿠키 세팅 (BE 몫)
- 실패 → 필드 아래 인라인 오류 ("이메일 또는 비밀번호가 올바르지 않습니다")

**API**: `POST /auth/login`

**⚠️ 스코프 노트**: 시연 계정 정보를 화면 하단에 회색 텍스트로 노출(`데모 계정: demo / demo123`). 심사장에서 심사위원이 직접 눌러 볼 수 있게. 실 배포 시 제거.

### 5-2. 상황실 대시보드 (`/dispatch`) · **메인 화면** ⚠️ 2026-09-04 정정 (레이아웃)

**레이아웃 (v0.2)**

```
┌─ 헤더 (로고 · 계정) ───────────────────────────────────────┐
├─ 좌 사이드 220px ─┬─ 결정 경로 배너 (상단, 강조) ──────────┤
│                    │  ★ 1순위 · 통과확률 94% · ETA 4:47      │
│  시나리오 리스트   │  근거 1줄 요약 · [근거 보기] [출동 확정] │
│  · 은행1동 234-5   ├─ 지도 (메인) ─────────────────────────┤
│  · 상대원1동 102   │  화재 지점 핀 · 관할 차량 아이콘        │
│  · 하대원 45-2     │  결정 경로가 굵게 · 미리보기는 반투명   │
│                    │                                          │
│                    ├─ 후보 경로 (지도 아래, 가로 2개) ──────┤
│                    │  [2순위] 통과확률 · ETA · 근거 1줄       │
│                    │  [3순위] 통과확률 · ETA · 근거 1줄       │
│                    │  카드 클릭 → 지도 미리보기 + [이 경로로 변경] │
└────────────────────┴──────────────────────────────────────────┘
```

**핵심 동작 (v0.2)**

1. **좌측 · 시나리오 리스트** — 미리 만든 3~5개 카드. 카드에는 `제목 · 위치 · 추천 차량 hint` 표시. 클릭 시 지도 이동 + `POST /route` 호출.
2. **상단 · 결정 경로 배너** — `POST /route` 응답 `rank: 1`이 자동으로 여기에 올라옴. 통과확률(큰 숫자)·ETA·거리·핵심 근거 1줄. 우측에 `[근거 보기]`·`[출동 확정]` 두 버튼.
3. **지도 · 화재 지점 · 차량 · 결정 경로** — Kakao Map. 클릭한 시나리오 위치에 빨간 핀, 관할 차량 아이콘, **결정 경로가 굵게(6px, 파랑)** 그려짐. 후보 경로는 지도에 상시 표시하지 않는다 — 화면이 어지러워진다.
4. **하단 · 후보 경로 카드 2개** (2·3순위) — 가로 정렬. 각 카드:
   - 순위 배지 (2·3)
   - 통과확률 % · ETA · 거리 · 미니 근거 1줄
   - 클릭 시 지도에 **미리보기**(연파랑 4px) 겹침 → 카드에 `[이 경로로 변경]` 버튼 노출
   - `[이 경로로 변경]` → 상단 결정 자리와 스왑, 지도에 굵게 다시 그림
5. **근거 카드 확장** — 상단 결정 배너의 `[근거 보기]` → 지도 위로 오버레이 시트가 내려오며 LLM 5줄·제외 링크 리스트·각 링크의 CCTV 스틸 미리보기 표시. `[닫기]`로 지도 복귀.
6. **`[출동 확정]`** — 상단 결정 배너 우측. 확정 시 토스트만(시연용). BE에 `POST` 하나 날림.
7. **차량 자동 선택** — `POST /route` 응답이 배차 정보를 준다. **몇 대·어떤 차종은 BE가 화재 규모로 결정** (§10-9 팀확정). 프론트는 응답을 그대로 표시.

### 5-3. 관할 지도 (`/map`)

**레이아웃**: 지도가 전체 화면. 좌측에 얇은(200px) 토글 패널.

**핵심 동작**

1. **오버레이 토글 2개**
   - `[ ] 정적 진입불가` — 중원구 PDF에서 뽑은 폴리곤. 회색 사선
   - `[ ] CCTV 판독 결과` — 배치 판독 결과. 링크 색상이 통과확률에 따라 그라디언트 (초록 → 노랑 → 빨강)
2. **차량 선택 드롭다운** — 상단. 선택하면 그 차량 기준 통과확률로 히트맵이 다시 그려짐 (`GET /coverage?vehicle_id=xxx`).
3. **골목 클릭** → 팝업
   - CCTV 스틸 이미지 (S3 → CloudFront)
   - 잔여폭 (m)
   - 감지 객체 (`parked_truck`, `trash_bin` 등)
   - 차량별 통과확률 표 (소형 · 중형 · 대형 세 줄)
   - 판독 시각 · 출처 (`batch_yolov11_sam2`)

**API**
- `GET /vehicles` (드롭다운)
- `GET /no_go?bbox=...&layer=1,3` (지도 이동 · 줌 변경 시 debounced)
- `GET /coverage?vehicle_id=xxx` (차량 변경 시)
- `GET /cctv/:edge_id` (골목 클릭 시)

**성능**
- `bbox` 조회는 지도 이동 250ms debounce
- `no_go` 결과는 React Query로 캐시 (같은 bbox·layer 조합은 5분 유지)
- CCTV 스틸은 CloudFront + `next/image` (한 번 뜬 이미지는 브라우저 캐시)

**핵심 동작**

2. **우측 · 상세**

   - `[관할 지도에서 커버리지 보기]` 버튼 → `/map?vehicle_id=xxx`로 이동
   - 커버리지 미니 히트맵 (썸네일)
   - 통과가능 도로 총 길이 (km) · 통과불가 도로 총 길이 (km)

**API**
- `GET /vehicles`
- `GET /coverage?vehicle_id=xxx` (썸네일용, 작은 bbox로 요청)

## 8. 데이터·API 사용

### 상태 관리 경계

| 상태 종류 | 저장소 | 예 |
|---|---|---|
| 서버 데이터 (재조회 가능) | **React Query** | `/scenarios`, `/route`, `/vehicles`, `/no_go`, `/coverage`, `/cctv/:id` |
| UI 로컬 상태 (컴포넌트 스코프) | React `useState` | 팝업 열림 · 폼 입력 |

| 세션 · 계정 | httpOnly 쿠키 (BE) + React Query `me` | 로그인 사용자 정보 |

**Zustand는 오직 UI 상태만.** 서버 데이터는 절대 담지 않는다 — 캐시 무효화·재조회를 React Query에 위임한다.

### API 계약 (팀장 v2 그대로)

- `POST /auth/login` · `POST /auth/logout` · `GET /auth/me`
- `GET /scenarios`
- `POST /route`
- `GET /vehicles`
- `GET /no_go?bbox=...&layer=1,3`
- `GET /coverage?vehicle_id=xxx`
- `GET /cctv/:edge_id`

### Mock → Live 격리막 (z-groupware 승계)

- 컴포넌트는 **UI 계약 타입만** 의존 (`types.ts`).
- `server.ts` / `actions.ts`가 `isMock` 분기 (mock | serverApi).
- **매퍼**가 BE shape → UI 계약 흡수. 연동 시 매퍼만 수정, 컴포넌트 0줄.
- **⚠️ BE 스펙은 v2 초안**이라 필드가 바뀔 여지가 크다 → 초반 2주는 mock 병행, 마지막 4일에 라이브 연결.

## 10. 열린 질문 · 팀 확정 필요

박종준(팀장) · BE 4명과 다음 결정을 맞춰야 한다. 각 항목에 **내(홍근) 의견 · 필요한 확정**을 붙였다.

### 10-1. 사용자 유형

- **내 의견**: 단일 사용자(상황실 담당자). 위 §1 근거.
- **확정 필요**: 팀장이 "출동대장용 별도 뷰"를 원하는지 여부. 원하면 스코프 재조정 필요.

### 10-2. 로그인 · 인증 세션 방식

- **내 의견**: httpOnly 쿠키 · 시연 계정 1개. 회원가입·비번찾기 없음.
- **확정 필요**: BE가 세션 발급 준비 되는지, 아니면 프론트에 API 키 하드코딩할지.

### 10-3. `/dispatch` 좌측 시나리오 리스트의 성격

- **내 의견**: BE가 준 `/scenarios` 3~5개 카드만. **수동 신고 입력 폼은 넣지 않는다** (심사 시 즉흥 데모 위험).
- **확정 필요**: 수동 입력 요구가 있는지. 있으면 폼 하나 추가.

### 10-4. CCTV 이미지 확보 · 라이선스

- **내 의견**: 유강현이 판독한 이미지 5~10장이 있어야 근거 카드·팝업이 뜬다. **한 장도 없으면 심사에서 골목 클릭 시 팝업이 텅 빈다** — 리스크 큼.
- **확정 필요**: 유강현 담당분 시연용 이미지 몇 장까지 준비 가능한지, D-10까지 S3 업로드 여부.

### 10-5. 다크모드 · 라이트모드

- **내 의견**: 다크 기본, 라이트 옵션 토글. 토큰 구조는 Day-1.
- **확정 필요**: 심사·시연은 라이트가 스크린 사진에 잘 나온다는 지적이 있을 수 있음. 심사장 조명에 따라 시연 직전 전환 가능하게.

### 10-6. 배포 · 도메인

- **내 의견**: Vercel + 임시 도메인 (`golmok119.vercel.app`). 커스텀 도메인은 v2 이후.
- **확정 필요**: 팀장이 Vercel 계정을 팀 공용으로 발급할지, 홍근 개인 계정으로 임시 진행할지.

### 10-7. `/dispatch` 확정 액션의 실제 처리

- **내 의견**: 시연용 POST 하나만 (토스트 후 끝). 무전·SMS·팩스 등 실제 출동 지시는 v3 이후.
- **확정 필요**: 팀장이 "확정 시 어떤 형태로든 로그가 남았으면 좋겠다"는 요구가 있는지 (로그 조회 화면이 필요해질 수 있음).

### 10-8. Kakao Map 사용 · API 키 할당

- **내 의견**: JavaScript SDK · 개발자 무료 할당량 (일 300,000회). 시연용으론 충분.
- **확정 필요**: 팀 공용 카카오 개발자 계정에서 도메인 등록 · 키 발급.

### 10-9. 화재 규모 기반 다중 차량 출동 로직 ⚠️ 2026-09-04 신규

- **배경**: v0.1은 "차량 한 대 자동 선택"이었으나, 실제 소방 운영은 화재 규모(주택 · 상가 · 공장)에 따라 **여러 대(펌프차·구급차·굴절차 조합)** 가 동시 출동한다. 프론트가 한 대만 표시하면 이 도메인이 통째로 사라진다.
- **조사 필요**:
  - 화재 등급별 표준 출동 편성 (소방청·성남소방서 지침)
  - BE `POST /route` 응답이 다중 차량 배차를 담을 수 있는 구조인지 (`routes[]`가 차량별로 나뉘는지, 아니면 별도 필드)
  - 화면에 여러 대를 어떻게 표시할지 (차량별 경로 카드? 하나의 결정 배너 안에 편성 요약?)
- **확정 필요**: 팀장·BE 4명과 이 도메인이 MVP 안에 들어가는지 여부 결정. **들어가면 §5-2 레이아웃 다시 손봐야 함.**
- **내 의견**: MVP는 "한 대 배차·한 경로"로 두고, 다중 차량 편성은 근거 카드에 "이 화재는 표준상 펌프차 2·구급차 1 편성" 텍스트로만 표시 → v2에서 각 차량별 경로 분리.

### 10-10. CCTV 판독 데이터 확보 (유강현 담당) ⚠️ 2026-09-04 신규

- **배경**: 유강현의 YOLO+SAM2 판독 결과가 없으면 `/map` 골목 팝업·`/dispatch` 근거 카드가 텅 빈다.
- **대기 지점**: 유강현이 어떤 이미지 몇 장을 어떤 스키마로 뽑을지 확정된 뒤 다음이 구체화 가능:
  - `GET /cctv/:edge_id` 응답의 `detected_objects` 실제 값 (지금은 `parked_truck`·`trash_bin` 예시만)
  - 스틸 이미지 URL 규약 (S3 경로 · 파일명 · 갱신 주기)
  - `measured_width_m` 정밀도 (소수점 몇 자리)

## 부록 · z-groupware에서 이어받는 규칙

이 문서에 명시된 것 외에 z-groupware `CLAUDE.md`의 다음 규칙은 별도 `CLAUDE.md`로 정리해 그대로 승계한다 (별도 작업):

- 폴더 구조 (`app/` · `components/` · `features/` · `hooks/` · `lib/` · `types/` · `constants/`)

- Server-First (조회=Server Component · CUD=Server Action + BFF · revalidatePath)
- 목록·페이지네이션 (스크롤 트리거 · id 중복 거름 · 전체 건수 헤더)
- 성능 (`next/image` · `next/font` · `next/dynamic` · CWV INP<200ms · CLS<0.1)
- 테스트 (Jest+RTL · `getByRole` 우선 · AAA · 로직/매퍼는 짜자마자)
- Git·PR (이슈 번호가 브랜치·커밋·PR을 잇는다 · `type: 제목 #이슈` · 한글 50자)
- AI 협업 (문서 4벌 정합 · 옛 결정에 `⚠️ YYYY-MM-DD 정정` · "고위험만" 지시 금지)
